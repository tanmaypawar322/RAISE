## PHASE 1: Jurisdictions, office routing and escalation ladder (foundation)

**Goal:** a citizen's issue reaches the right office automatically, and has a defined next level when ignored.

1. **Jurisdiction model:** `Jurisdiction` {id, name, nameMr, nameHi, level (`ward|zone|corporation|district|state|centre`), parentId, boundary (GeoJSON Polygon/MultiPolygon, optional, 2dsphere indexed), code}. Seed structure only via import; no invented real data.
2. **Office model additions:** link each `Office` to a `jurisdictionId`, a `department` key and an `escalatesToOfficeId` (next level up the ladder).
3. **Category-to-department mapping:** `CategoryRouting` {category, jurisdictionLevel, department, defaultOfficeLookup}. Editable by admin; stored as data, not hard-coded.
4. **Auto-suggestion:** `POST /api/issues/suggest-office` takes `{lat, lng, category}` and returns ranked suggested offices: find the ward polygon containing the point (`$geoIntersects`), then map category to department and find the office in that jurisdiction (fall back to the parent jurisdiction). If no polygon data exists, fall back to the user's `homeWard` and then to manual choice. The citizen can always override.
5. **Escalation ladder:** when an issue passes its SLA with no acknowledgement (or is reopened N times), a scheduled job records an `Escalation` event {issueId, fromOfficeId, toOfficeId, reason, createdAt}, shows "Escalated to <office>" on the public timeline, notifies both offices (hook into Phase 4), and lets the next-level office respond. SLA values per category/office are data (`slaHours`), default 48h acknowledge / configurable resolve.
6. **Import tooling:** `npm run import:jurisdictions -- file.geojson|csv` and `npm run import:offices -- file.csv` with validation, dry-run mode, and a clear error report. Provide sample CSV/GeoJSON templates in `backend/data/templates/` with obviously fake `[SAMPLE]` rows.
7. **Admin UI:** manage jurisdictions, offices, category routing and SLA values (list, edit, import preview). Admin-only, audit-logged.
8. Existing "tag office manually" behaviour keeps working as the override path.

## PHASE 2: Issue lifecycle: resolution proof, citizen confirmation, duplicates and merge

### 2A. Resolution proof and citizen confirmation
1. Statuses: `submitted -> published -> acknowledged -> in_progress -> resolved_pending_confirmation -> resolved | disputed (reopened)`; plus `rejected` (with required reason). Add `resolvedUnconfirmed` as a labelled final state (below). Migrate existing statuses safely.
2. To mark an issue resolved, an official/agency member of the **owning office** must provide: a public note (required) and **at least one "after" photo** (or an explicit exception reason such as "no physical work required", shown publicly). Reject the request with 422 otherwise.
3. Server records an after-photo's upload timestamp. If the photo has GPS metadata, compute distance to the issue location and flag (not block) when it exceeds a configurable radius (default 150 m); strip metadata before serving publicly.
4. After "resolved_pending_confirmation", the reporter and supporters in the same ward (verified accounts, one vote each) can **Confirm** or **Dispute** within `CONFIRM_WINDOW_DAYS` (default 7). 5. If the window passes with no dispute: the issue becomes `resolved` labelled "Resolved (unconfirmed by citizens)". If at least one confirmation arrives: "Resolved (confirmed by N citizens)". Show before/after photos side by side on the issue page.
6. Official notes cannot be deleted; corrections create visible edit history (reuse existing audit pattern).
7. Objects-level authorization: only members of the owning office (or its escalation office, or admin) can change status. Add IDOR tests.

### 2B. Duplicate detection and merge

In the Raise flow, after location + category are chosen, call `GET /api/issues/similar?lat&lng&category&text`: return open issues within a configurable radius (default 100 m, same category family, last 90 days) ranked by distance and text similarity (use a MongoDB text index and simple token-overlap scoring; no external AI service). Show up to 3 suggestions: "Already reported? Raise it instead".

3. **Merge tool** for moderators, admins and the owning office admin: choose a canonical issue and merge others into it.
